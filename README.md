## 制約
- 全体のファイルサイズが 1,474,560 バイト（1.44MB）以下
    - 圧縮解凍後の全体の容量が基準以下でなければなりません（ゲーム内での圧縮の使用は許可されていますが、最終的な実行可能状態の総ファイルサイズが制限内に収まる必要があります）。
- 独立した実行ファイル（スタンドアロン）としてプレイ可能。ウェブブラウザゲームは禁止。

## プロジェクトの詳細
ユーザーがアップロードした画像を、その場で画像の中の要素に基づいてピースに分割してパズルを作成。たとえば、建物の写真なら、窓・扉・屋根といった具合に。
ユーザーは、そのピースを並べていって、元の画像を完成させることでゲームクリア。

- 画像ファイル: JPEG および PNG に対応 (軽量ライブラリ `stb_image.h` を採用)
- Windows対応を基本とする。（TODO: Macにも対応できる？）
- パズルピースの仕様とデータ構造
  - ピースは「元画像への参照」と「元画像のピクセル座標のリスト」、および「隣接するピースIDの集合(Set)」を保持する。ピクセルごとの色・相対座標は持たない（メモリ節約）。
  - ピクセル群の所属グループ（ピースID）の管理には **Union-Find木（素集合データ構造）** を利用して計算を高速化する。
  - **隣接情報の更新**: ピースAとピースBを結合する際、Union-Find木上で親を統合し、両者の「隣接ピースIDリスト」を和集合としてマージする（AとB自身のIDは除外）。
- ピースの自動生成と結合 (フラグメンテーション)
  - アルゴリズム方針: 画像をレトロ調（減色・低解像度化）に加工後、「1ピクセル＝1ピース」の初期状態から開始するボトムアップ方式を採用。
  - 「面積が一定以下の極小ピース」と「色が最も近い隣接ピース」を見つけ、Union-Find木を用いて結合を行う。これを全ピースが一定面積に達するまで繰り返す。
- ユーザー操作によるピースの結合判定（プレイ中）
  - 判定対象の絞り込み: ピース自身が保持している **「隣接するピースIDの集合(Set)」のみを判定対象** とする。空間分割（グリッド管理）などのデータ構造を持たないことで、メモリとコード量を削減しつつ計算量を最小化する。
  - 結合条件:
    1. 角度がほぼ一致しているか。
    2. 動かしたピースの現在位置と角度から「もう一方のピースが本来あるべき座標」を算出し、実際の座標との距離が許容範囲内か。
  - 結合時の演出: ピースが正しくハマった時に、短い「カチッ」「コトッ」という効果音を流す。
- アートワーク（GUI）方針: 『The Incredible Machine』のような「アナログ・机の上（物理的なピース）」スタイル。
  - 容量削減のため、背景画像は使わず「無地（またはプログラムによるシンプルな塗りつぶし）」とする。
  - UIのアイコン画像も極力削り、テキストやプログラム描画の図形で表現する。
  - UI_Layout.pngにレイアウトの例を示す。
- 演出の要件: パズルが組み上がり、レトロな画像が完成した直後、元の高画質なきれいな写真へと鮮やかに復元されるトランジション演出を入れる。

## 技術スタックと構成
- 言語: C/C++
- ビルドツール: CMake
- GUI: **SDL2** を採用
  - 1.44MB制限をクリアするため、「静的リンク ＋ コンパイラ最適化(`-Os`) ＋ UPXによる実行ファイル圧縮」を必須工程とする。
  - レトロな雰囲気（無地背景、ミニマルなUI）をSDL2の2D描画機能で実装する。
- 画像処理/アルゴリズム: `stb_image.h` で読み込み。分割は「減色（レトロ化）」後の画像に対し、Union-Find木によるボトムアップの領域結合アルゴリズムを採用。
- 音声再生: 短い効果音（WAVまたはプロシージャル）のみ。(TODO: 再生用ライブラリとして `miniaudio` などを技術検証で試す)

## セーブ・ロード機能の仕様 (Save/Load Specification)
独自バイナリ形式を用いたセーブ機能を実装する。1.44MB制限を考慮し、JSONなどの外部パーサは使用せずC標準関数(`fread`/`fwrite`等)を用いる。
※ セーブデータファイル自体は1.44MB制限の対象外であるため、元画像消失への対策として画像データそのものをセーブファイルに埋め込む。

**保存データ構造案**
1. **[画像データ]** 元画像のファイルサイズ(バイト数) ＋ 画像ファイルのバイナリデータ本体
2. **[配列]** 各ピクセルの所属ピースID (`Width × Height` 個の整数配列)
3. **[配列]** 現在存在する各ピースの状態 (`x`, `y`, `is_in_inventory`) の配列

## 開発・ビルド方法 (Build Instructions)
このプロジェクトはCMake、Ninja、およびMSYS2 (UCRT64) のGCCツールチェーンを利用してビルドします。

1. **ターミナルの準備**
   VS Codeのターミナル、またはスタートメニューから「MSYS2 UCRT64」を起動します。

2. **ビルド環境の初期化 (初回のみ)**
   プロジェクトのルートディレクトリで以下のコマンドを実行し、ビルドファイルを生成します。
   ```bash
   cmake -B build -G Ninja
   ```

3. **コンパイルとビルド (コード変更後)**
   コードを書き換えた後は、以下のコマンドでビルドを実行します。
   ```bash
   cmake --build build
   ```
   ※ ビルド成功後、自動的にUPXによる実行ファイルの極小化（圧縮）が行われます。

## 実行方法 (How to Play)

ビルドが完了すると、`build` フォルダ内に最終成果物である `JigsawMachine.exe` が生成されます。

**ターミナルから実行する場合:**
```bash
./build/JigsawMachine.exe
```

**エクスプローラーから実行する場合:**
`build` フォルダを開き、`JigsawMachine.exe` を直接ダブルクリックして起動します。
